# VaultCenter languages

The interface offers French and English on the sign-in page and in the library front panel. On first access, the browser language is used if it is English; French is the fallback. An explicit choice is stored locally (`vaultcenter-language`) and synchronised between tabs. Forms, tape selection and readings are not reset when the language changes.

Dates, numbers, units and plurals follow the chosen language. Library and bucket names, barcodes, paths, commands and protocol identifiers stay as they are. Technical diagnostics that are not in the catalogue remain visible without an approximate translation.

Emails have an independent language, set in Settings → Notifications. French remains the default value for existing installations. The subject, text, HTML and examples follow this setting at the time of sending, including for emails already queued. Changing the interface language does not change this server setting.

## Adding a message

- Use `useI18n()` in a component that displays translations; presentation functions can use `translate` and `getLocale`.
- Keep the French text as the key and add the translation in `ui/src/lib/locales/en-{core,media,storage,admin}.ts`.
- Translate a complete sentence with `{name}` parameters, keeping the same parameters in both languages. Use `isPlural(count)` for display plurals.
- Keep status codes and user data. HTTP errors are distinguished through `ApiError.status`, never through their translated text.
- Use `localizedToast` for transient notifications. Their content follows the language without changing the durations or actions.
- Do not add the language to polling dependencies or to keys that remount forms.

## Checking

From `ui/`:

```sh
node tests/i18n-unit.mjs
npm run build
node tests/i18n.mjs
```

The French acceptance tests explicitly set `locale: 'fr-FR'`. The bilingual flow checks the sign-in/S3/email drafts, roles, confirmations, units, custom names, persistence and mobile layout in both themes. The Rust notification tests also check older configurations, language validation and HTML escaping.

## Compatibility

A recent interface hides the email language setting when the older API does not offer it. Once the `language` field is saved in `notification_settings.configuration`, going back to an older API requires removing this JSON field: its decoder refuses unknown fields. Do not restore an old database wholesale, as this would lose the operations performed since.
